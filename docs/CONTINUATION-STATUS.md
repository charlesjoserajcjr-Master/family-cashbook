# Family files, currency ledger and billing continuation

The new continuation is local until the next branch push. PR #1 stays in draft; no merge or deployment has been performed.

## Implemented in this continuation

- **Encrypted family file exchange:** separate ECDSA/ECDH member identities, passphrase-encrypted private-key vaults, owner-signed viewer/editor grants, recipient-specific AES-GCM files and independently verified fingerprints. The owner sends scoped snapshots; editors return signed proposals that the owner reviews. Private account records/amounts and aggregate features are removed before encryption. Native sharing uses the device share sheet; Windows can save an attachment for WhatsApp/email. File selection imports saved attachments.
- **Enforcement:** the standalone write API rejects viewer writes and editor changes outside granted account scopes. The owner's receiving boundary independently checks signatures, current grants, role, epoch, base sequence, replay IDs, account scope and closed periods. Tests include custom hostile clients with valid signatures. Local UI flags are not the receiving authority. Import preserves the owner's unshared balance fields/transfers and requires conflict resolution rather than silently overwriting concurrent owner edits.
- **Revocation and recovery:** removed grants reject outstanding proposals; remaining members need refreshed files after epoch rotation. Existing downloaded/cached copies cannot be erased. Restoring an owner backup clears all member grants instead of reactivating old invitations. Re-pairing after owner recovery requires explicit confirmation of the same owner fingerprint. Keep one authoritative owner ledger; personal Drive sync is disabled for family ledgers to avoid competing membership histories.
- **Native-currency account ledger:** native account balances, income/expenses, foreign card debt/credit, recorded transaction rates, dated INR valuation history, native monthly budgets, reviewed month-end balances, remittance source/received amounts and source fees. Transfers to/from legacy INR accounts affect those accounts once; principal is excluded from income/expense. Home and net worth include the INR valuation. Missing rates are explicit. Currency history CSV uses formula-safe cells.
- **Currency scope:** legacy accounts, categories, business, loans and daily tables retain their INR semantics. Foreign accounts have a dedicated workspace and INR reporting. This avoids relabelling existing INR amounts as foreign money. There are no live FX feeds, tax calculations, automatic NRE/NRO eligibility decisions or currency-specific loan amortization. Foreign monthly budgets and confirmed balances participate in forecasts/close review.
- **Billing integration code:** Razorpay web checkout, RevenueCat native purchase/restore SDK bridge, a local/deployable Node billing service, key-proof owner login, durable SQLite purchase/event state, raw-body webhook validation, provider-side refresh/ownership checks and signed entitlements. Trial/cancelled/refunded/expired states, duplicate events, uncertain checkout acknowledgements, multiple providers and sandbox/live separation have automated tests. Cached signed access is bounded to 72 hours and never beyond paid-through time. An editable local paid flag is not accepted.
- **Non-destructive purchase rollout:** purchasesEnabled defaults false, all merchant/client IDs and keys are blank, and existing tools/records/export stay available. Live billing has not been activated or tested because the owner has no merchant/store accounts yet. A fully refunded Razorpay subscription is conservatively revoked; support must reconcile it or a new subscription is required. Signed cached access cannot guarantee immediate offline revocation.
- **Native build verification:** new PR-only, contents-read CI jobs prepare isolated preview identities. Android builds a debug APK and runs an emulator filesystem/encryption/kill/reopen test; Windows runs an Electron file/encryption/close/reopen test and packages an unsigned portable preview; iOS builds, installs and launches on a simulator without signing. These jobs do not create releases, upload to stores or deploy Pages.
