# Migration, backup and recovery

1. Export the original ledger before trying this branch. Keep that original backup separately. Test using a copy and synthetic records first.
2. Existing JSON records are retained. Budget categories now retain the unspent portion of their plan; use Single bill for a single confirmed payment or mark a category complete when no further activity is expected. Review migrated forecasts before relying on them.
3. Monthly bank entry no longer closes earlier months automatically. Open More → Monthly review, enter each real balance, then Review and close. Review the actual-only comparison for each account. Explain unrecorded differences even when they offset to zero overall. Close the earliest open period first.
4. Review credit cards. Enter their opening debt as a negative account balance. Purchases are expenses; repayments are bank-to-card transfers. Link any existing manual card liability to its account in Net worth so it is not counted twice. Positive card balances are assets, not liquid bank cash.
5. Optional working-ledger encryption: first export and test a recovery backup on a disposable copy. Disconnect Drive, open More → Privacy & encrypted backups, choose and confirm a long unique passphrase, then enable encryption. Use Lock now before handing over a shared device. Reopening requires the passphrase. No automatic idle/background lock or biometric protection is implemented.
6. The passphrase cannot be recovered or reset by ReadyTrove. Keep it separately from backups. Older plaintext exports, previous desktop daily backups, synced copies and operating-system backups remain plaintext unless separately migrated or removed. Encryption protects saved content, not a compromised device while unlocked.
7. New working-ledger writes and Drive uploads are encrypted while the ledger is encrypted. Export defaults to encryption while enabled. Use the same ledger passphrase on other personal devices; this is not a separate-member sharing mechanism. Do not share a Google password.
8. Restore validates the entire candidate before changing the ledger. A recovery export of the current ledger is offered first; cancelling the desktop save aborts the restore. Browser downloads and native sharing do not prove a file was kept—verify the recovery file yourself before confirming a restore. Restored values get new field revisions and can propagate to connected devices.
9. On read corruption, editing is blocked. Use Export original source to preserve the exact unreadable file, then select a known valid backup. Wrong passphrases or invalid imports leave the original untouched.
10. On a save error keep the app open, export the recoverable state and use Retry save. Electron close should wait for saves; browser and mobile shutdown cannot guarantee an asynchronous write completes. Native writes use a temporary file and rename so the previous ledger remains available if writing is interrupted. Test device behavior before release.
11. Drive precondition, duplicate-file or repeated conflict errors stop upload. Export every local and remote copy before manual recovery. Do not delete copies simply to clear an error. Real Drive precondition behavior is still unverified.

No limit or subscription gate is introduced by this branch. Existing data, basic exports, business and net-worth tools remain accessible. Prices on Plans are proposals, not an active purchase offer.
